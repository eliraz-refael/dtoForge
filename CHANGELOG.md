# Changelog

All notable changes to DtoForge will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), 
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Enhanced TypeScript output with interface-based types by default
- New configuration option `useInterfaces` (default: `true`) for choosing between interfaces and type aliases
- Cross-platform NPM package support with proper binary installation
- Support for `npx dtoforge` usage without installation
- Better error handling and cross-platform compatibility in NPM package

### Changed
- **BREAKING:** Removed "Codec" suffix from generated TypeScript types (`User` instead of `UserCodec`)
- **BREAKING:** Changed default values for generation options:
  - `generateHelpers`: `true` → `false`
  - `generatePartialCodecs`: `true` → `false`
  - `generateSchemaRegistry`: `true` → `false` (new option)
  - `generateSchemaNames`: `true` → `false` (new option)
- **BREAKING:** TypeScript output now uses `t.intersection` pattern for better required/optional field handling
- **BREAKING:** Interface-based types are now generated by default (`interface User extends t.TypeOf<typeof User> {}`)
- Simplified enum generation to use inline `t.keyof` without separate values object
- Improved NPM package installation with platform-specific binary wrappers

### Fixed
- NPM global installation now works correctly on all platforms
- Binary execution permissions on Unix-like systems
- Cross-platform path handling in NPM package
- Package.json binary path consistency

## Previous Releases

---

**Migration Guide for v1.x:**

If you're upgrading from an earlier version, note these breaking changes:

1. **Type Names**: Remove "Codec" suffix references in your code (`UserCodec` → `User`)
2. **Configuration**: Update your config file to explicitly enable features that were previously on by default:
   ```yaml
   generation:
     generateHelpers: true          # if you need helper functions
     generatePartialCodecs: true    # if you need partial type variants
     generateSchemaRegistry: true   # if you need schema registry object
     generateSchemaNames: true      # if you need schema names array
     useInterfaces: false           # if you prefer type aliases over interfaces
   ```
3. **Import Patterns**: Update your imports to match the new interface pattern or configure `useInterfaces: false`

These changes significantly reduce bundle size and improve migration compatibility for projects upgrading from Swagger 2.0 to OpenAPI 3.0.
